## 一、核心承诺（七条）

| 编号 | 承诺 |
|---|---|
| **C1** | **文档数据不进入任何网络请求，也不进入任何 AI 模型的训练 / 微调 / 评测语料。** 本技能不收集、不上传、不缓存、不回传任何文档内容。**联网按「数据出域」分四档，不按"有没有联网"一刀切**（v3.23.3 起 `scripts/` 下共 **23 个脚本**）：**L0 绝对离线 18 个**——凡接触文档正文、脱敏映射表或私有规则的脚本，**零网络库、零出网路径**；这是唯一保留的一刀切，但它切在「**接触文档**」上，不切在「联网」上。**L1 在线只读 1 个**——`version.py` 查更新，只 GET 一份公开版本清单，**默认关闭**（须显式 `--check-online`）。**L2 不联网就用不成 2 个**——`legal-parse.py` 抓公开法规页、`freshness-patrol.py` 调它做法规库失效巡检；**法条是否已修订，不联网无从得知**，故这一档必须能联网，代价换到别处补：**须显式调用**、**不出现在审查链路上**、离线时明示降级而非静默假成功。**L3 门禁自检 2 个**——`check.py`、`smoke-test.py` 持有网络关键字清单用于检查别人，自身不发起联网。**四档同一条红线：任何一档的请求里都不含文档内容、文件名、映射表或私有规则。** 联网本身不是风险，**带着文档出去才是**——所以这里承诺的是"文档不出域"，不是"不联网"。逐档名单与自检命令见第五节。 |
| **C2** | **不改动原始文件。** 原件只读、永远留存；全部交付物均为新建文件。 |
| **C3** | **最小必要。** 只读取必要范围；脱敏只脱必要类别；凡数据出域，**先脱敏**。 |
| **C4** | **脱敏可逆、映射表隔离。** 映射表（含真实值的明文对照表）默认只落**本机隔离目录** `~/.dcr-maps/`，**不随交付物外发**；可 `--irreversible` 选择不生成映射表。 |
| **C5** | **涉密文件不进模型。** 读取全文前**先问一句「这份文件能不能给 AI 看」**（读全文＝把整份文件交给 AI 看，属数据出域），确认密级后再决定；涉密文件走**纯本地链路**（本机提取清洗 → 本机正则脱敏，全程不联网、不调用 AI）。 |
| **C6** | **输出可隔离、可限权。** 交付物按文档名自动分目录存放；输出目录可关闭权限继承、仅授权本机指定账户（只改权限、不删文件）。 |
| **C7** | **不代装依赖、联网取更新由使用者先开口。** 依赖缺失时只**生成安装命令**（`detect-tools.py --install-guide`，可写成脚本文件供核对），**执行与否由使用者决定**；**从不自动下载、从不自动安装**新版。版本检测支持两条路：**本地源**（目录或未解开的 zip，`--watch` 登记，全程不联网）；**在线源**（只 GET 一份公开版本清单）**默认关闭**，须使用者显式 `--check-online`、或把 `update.check_online_by_default` 显式设为 true 才生效。默认配置下 `version.py` **一个请求都不发**。 |

**"是否用于训练模型"须分两层看**：**本技能层完全可控**——文本提取、清洗、脱敏、Word/Excel/PDF 生成**全部在本机完成**，可断网运行，**不产生任何训练语料、不做任何数据上传**；使用"只要脱敏、不要审查"或"纯本地链路"时，**文档内容根本不进入任何模型**。**模型层须由使用方确认**——"审查判断"一步需把文档**全文读入模型上下文**（架构决定），该层数据是否用于训练**取决于所用平台/服务商的策略，非本技能所能控制**。

> **使用方义务**：提交文档前应确认所用平台处于**"不用于训练"**状态（优先**私有部署 / 企业版 / API 直连**，并关闭"改进服务 / 用于模型训练"类选项）；**无法确认时，按涉密处理**，改用纯本地链路。
> **使用红线**：**禁止**将文档用于模型训练、微调、评测集构建、案例库或公开演示（含人工标注与二次加工）。

## 二、数据流转四条路径（风险由低到高）

| 路径 | 数据是否出域 | 适用 |
|---|---|---|
| 1. **纯本地链路**（`local-only.py`） | **不出域** | 涉密 / 敏感 / 批量个人信息 |
| 2. **脱敏后出域**（`desensitize.py` / `local-only.py`） | 仅脱敏文本出域 | 准敏感，仍需模型判断 |
| 3. **全文出域**（标准审查流程） | 全文进模型上下文 | 非涉密一般商务文档 |
| 4. 纯提示词平台（粘贴文本） | 全文进对话上下文 | 低敏文档 |

## 三、脱敏口径与命令（两类，勿混用）

| 口径 | 默认脱哪些 | 用途 |
|---|---|---|
| **审查用** | **6 类**：证件号 / 电话 / 银行 / 邮箱 / 邮编 / IM（**保留**信用代码、绝对金额、地址、人名） | 主体尽调、阈值比对 |
| **对外出域** | **10 类全脱**：＋ 信用代码 / 绝对金额 / 地址 / 人名 | 一切外发件 |
| 比例数字（如 30%） | **不脱** | 保留合同可读性 |

> **电话与 IM 是"总类"**：座机与手机只是电话的两种写法（一并归入电话），微信／钉钉／QQ／脸书／微博
> 只是不同的即时通讯工具（一并归入 IM）。写法千变万化、工具年年新增，逐一枚举必然挂一漏万，
> 故按总类识别、统一打 PHONE / IM 标签——规则更少，漏网更少。

- **命令**：审查用 `desensitize.py mask <文件>`（默认 6 类，需全脱再追加 `--types`；确切人名 `--names` 兜底）；**对外出域 / 涉密文档不进模型** 用 `local-only.py <文件>`（默认 10 类全脱，本机提取＋脱敏、不联网、不调用 AI）；无需回填时加 `--irreversible` 可不生成映射表（更安全）。
- 映射表默认 `~/.dcr-maps/`（可用 `--map` 或环境变量 `DCR_MAP_DIR` 改位）；**只留本机、勿随交付物外发**。
- 脱敏为**去标识化 / 伪名化**，**可逆回填，不等同于匿名化**；外发前请自行评估风险。

## 四、操作红线（"八不"）

1. 不把含个人信息 / 商业秘密的**原文**直接提交公有云（先脱敏或走本地链路）。
2. **不**把映射表（`.map.json`）随交付物一并外发。
3. **不**把清洗稿 `.clean.txt` 当外发件（它是本机工作底稿）。
4. **不**把 `private/`（企业内控私有库）打包外发。
5. **不**将文档用于训练 / 微调 / 评测 / 案例库 / 公开演示。
6. **不**跳过「先问能不能给 AI 看」就处理涉密文档。
7. **不**在同一输出目录平铺混放多客户文档。
8. **不**忽略脚本指纹告警（校验不一致即暂停使用）。

## 五、已内置的技术措施

| 措施 | 说明 |
|---|---|
| 联网分级（安全引擎） | 不按"有没有 urllib"一刀切，按**数据出域**分四档：`L0` 接触文档的 **18 个脚本零网络库**；`L1` **1 个**（查更新，默认关）；`L2` **2 个**（法规抓取／失效巡检，**不联网做不成**，故允许联网但须显式调用、且不在审查链路上）；`L3` **2 个**（门禁自检，自身不联网）。**任何一档都不携带文档内容出网**。依赖仅标准库＋ `python-docx`/`openpyxl`/`Pillow`；除"审查判断"（模型层，由平台决定）与"法规时效巡检"（L2）外**全部环节可离线完成**，关掉在线项后功能不降级 |
| 无缓存留痕 | 脚本禁止生成 `__pycache__`；`check.py --clean` 可清残留 |
| 脚本防篡改 | `check.py --sign` 建指纹基线、`--verify` 校验，被改动即告警 |
| 无执行策略绕过 | 校验用纯 Python `check.py`，不需要 PowerShell 执行策略绕过参数 |
| 打包默认剔除私有库 | 分发打包默认排除 `private/`，并复查包内是否混入 |
| 企业词表外置 | "去企业化"检查所需的企业/客户名称**不写入脚本源码**，改存 `private/deidentify-words.txt`（随 `private/` 被排除，不随发布包外流）；检查器自身不含任何企业名 |
| 安全调用本机工具 | 仅以参数列表方式调用本机 LibreOffice / Poppler / Tesseract，无 shell 拼接、无注入面 |
| 私有库默认空 | 根 `rules.md` 为空库、示例移入 `_template/`，避免企业未填写时示例规则误生效 |
| 输出隔离与限权 | 按文档名分目录；可选关闭权限继承、仅授权本机账户 |

**联网档位自检（两问两答）。**

**问一：每个脚本属于哪一档？** 下面是**当前全部 23 个脚本的逐一定档**（与脚本源码里的自标一一对应，
`check.py` 每次自检都会拿它与代码比对，**改一边不动另一边当场报错**）：

```
L0: _config.py desensitize.py detect-tools.py guard.py harden-dir.py imbalance.py legal-crosscheck.py legal-verify.py local-only.py make-docx.py make-header.py pack.py preprocess.py rule-baseline.py sample-baseline.py set-workdir.py tpl-engine.py verify.py
L1: version.py
L2: freshness-patrol.py legal-parse.py
L3: check.py smoke-test.py
```

一次命令即可复核（输出应当与上面四行**逐字相同**）：

```bash
grep -h "^# net-tier:" scripts/*.py | sed 's/# net-tier: //' | sort   # 看代码里的自标
python scripts/check.py | grep "安全引擎"                              # 看门禁比对结论
```

**问二：默认会不会自己发请求？** **不看代码、只看行为**的核验（更能说服客户 IT）：
清空 `config.json` 的 `update` 段后跑 `python scripts/version.py --notice`，**零输出、退出码 0** 即证明默认不发请求。

若改用"搜网络关键字"的办法（更原始，但客户 IT 爱用），**判据不要看总数，要看档位**：
命中名单里**只要出现任何一个 L0 档脚本，就是问题**；出现在 L1／L2／L3 档则属正常。

```bash
python -c "import pathlib; ks=('requests','urllib','socket','http.client','aiohttp','httpx','curl','wget','Invoke-WebRequest','smtplib'); print(sorted(f.name for f in pathlib.Path('scripts').glob('*.py') if any(k in f.read_text(encoding='utf-8',errors='ignore') for k in ks)))"
```
> 当前实测命中 `check.py`、`legal-parse.py`、`smoke-test.py`、`version.py` 四个，但**这个名单会随重构变化**
> （例如 `check.py` 把关键字清单改成正则后就不一定命中），故文档不把它写死成"预期 N 个"——
> **写死数字就会在某次重构后自证伪**（本项目已因此栽过三次）。看档位，不看总数。
>
> `check.py`／`smoke-test.py` 属"**检查器自指**"：里面写着用来扫描别人的关键字或正则，
> 自身不 import 任何网络库、也不发请求。`freshness-patrol.py` 通常不出现在该名单里——
> 它不自带网络库，联网经 `legal-parse.py` 完成，网络代码因此**集中在唯一一处**，比"每个联网脚本各写一份"更利于审计。

**安全机制逐条自检（12 条）。** 联网分档只回答"数据出不出得去"；下面这张表回答**全部**安全承诺——
每条都有编号、都有机械判据，**漏一条、废一条都会被门禁拦下**（判据直接指向正在跑的实现，
实现被删或修改，登记表当场报错，不会留下"写了但没做"的空头承诺）：

| 编号 | 机制 | 层 | 怎么验 |
|---|---|---|---|
| M1 | 文档不出域：接触文档正文／映射表／私有规则的脚本，零出网路径 | 数据层 | 逐档比对脚本自标 |
| M2 | 映射表隔离：默认落本机隔离目录，不随交付物走 | 数据层 | 读隔离目录配置并断言 |
| M3 | 私有库默认不打进发布包 | 数据层 | 复算打包排除项 |
| M4 | 查更新默认不发请求（可联网 ≠ 会自动联网） | 数据层 | 断言默认开关为关 |
| M5 | 原件不改：产物一律新建，源文件零写入 | 产物层 | **跑完比 sha256**（行为判据） |
| M6 | 输出隔离：按文档名分目录，多客户不混放 | 产物层 | 断言隔离开关为开 |
| M7 | 私有库默认空：规则库为空库，示例不误生效 | 数据层 | 门禁内既有检查项 |
| M8 | 不留缓存：脚本禁止生成 `__pycache__` | 代码层 | 门禁内既有检查项 |
| M9 | 脚本防篡改：指纹基线覆盖全部脚本，漏一个即报 | 代码层 | 比对基线与目录全集 |
| M10 | 无 shell 注入面：本机工具按参数列表调用，无拼接 | 代码层 | 按调用形态扫描 |
| M11 | 不代装依赖：只给命令，不替使用者执行安装 | 代码层 | 扫描代装调用 |
| M12 | 企业词表外置：脚本内不含任何企业／客户名称 | 代码层 | 门禁内既有检查项 |

一次命令看全部 12 条的当次结论：

```bash
python scripts/check.py | grep "安全机制"     # 输出：12 条在册逐条落实（数据层 5／产物层 2／代码层 5）
```

其中 **"原件不改"用的是行为判据而非静态判据**：冒烟测试会在跑完全流程后，
重新计算源文档的 `sha256` 并与跑之前比对——**不相同即失败**。
（grep 只能证明"代码里没写"，证明不了"运行时没做"；能证明后者的是跑完再比一次。）

## 六、合规对标与边界

- **合规对标**：《个人信息保护法》最小必要（6 条）、告知同意（13、14 条）、委托处理（21 条）、去标识化与匿名化定义（73 条）｜《数据安全法》分类分级、重要数据与出境管理 ｜《民法典》501 条（缔约中知悉的商业秘密）、1032–1039 条（隐私权与个人信息保护）｜《反不正当竞争法》商业秘密保护。
- **边界与免责**：1. 本技能**不做技术性匿名化认证**，不承诺达到任何特定标准（如 GB/T 35273 匿名化要求）；2. 脱敏为可逆伪名化，**能回填即意味着仍可还原**；3. 模型层数据处理条款由**平台**决定，本技能无法代为承诺，"不用于训练"须以平台策略与使用方确认为准；4. 处理文档须取得**合法授权**，超出授权范围的后果由使用者自负；5. 本声明为**安全性说明**，不构成法律意见，重大合规事项请咨询专业机构；6. **许可**：个人自用可；**商业使用须事先取得作者书面授权**；7. **第三方工具**：LibreOffice／Poppler／Tesseract／ImageMagick 等由使用者**自行安装获取**，其**版权与许可归各自权利人**，本技能不对其主张任何权利，使用者应自行遵守各自的许可条款。

## 七、使用前自检（30 秒）

每批处理前先过这 5 问：1. 这批文档**是谁的**、我是否已获处理授权？2. 是否含**个人信息/商业秘密/涉密等级**？→ 是，改走 `local-only.py` 纯本地链路。3. 所用平台是否已确认**不用于训练**？未确认 → 按涉密处理。4. 交付物发给谁？**映射表与 `.clean.txt` 是否已排除在交付之外**？5. 输出目录是否需要**限权**与**按文档隔离**（默认已开）？
