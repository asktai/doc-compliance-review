# 安装使用教程

**文档合规审查助手AI合同**

> 本教程是**手把手走一遍**：怎么装、怎么配、怎么自检、怎么跑第一次审查。
> 查功能、查参数、查常见问题 → `README.md`（技能手册）；查许可与免责 → `LICENSE.md`；完整执行口径 → `SKILL.md`（技能入口）。都在技能目录下。

---

## 一、开始之前：一个包，两种用法

发布包按**四段式**命名：`中文产品名_版本号_日期_(技能ID).封装格式`，**默认同时出 `.skill` 与 `.zip` 两种**。规范示例：

```
文档合规审查助手AI合同_v3.26.11_20261029_(doc-compliance-review).zip
└─产品名─┘└版本号┘└─日期─┘└────技能ID（slug）────┘└封装┘
```

本技能出包即得**两种各一份**：上面示例的 `.zip` 换成 `.skill` 即是（内容完全相同，见下）。

**四段定式**：版本号**带小写 v**（`v3.26.0`，不是 `V3.11.10` 也不是裸 `3.11.10`）、日期**紧凑
8 位**（`20261021`）、技能 ID **由半角括号包裹置末且为 slug**（`doc-compliance-review`）、
分隔符**一律下划线**。

四段**全部自动读取、不靠手填**（参见 `scripts/pack.py` 的 `package_stem`）：产品名 ←
`SKILL.md` frontmatter 的 `display_name`，版本号 ← `version`（统一补小写 `v`），日期 ← 打包当天
（紧凑写 `%Y%m%d`），括号段 ← `name`（slug，与技能目录名同一套标识）。这样"版本升了文件名还
写着旧号"的问题从根上不会发生。解压后第一层是技能目录 `doc-compliance-review/`，进去才是 `SKILL.md`。

> **两处使用提醒**：(1) 文件名含**成对半角括号**，终端里操作要加引号或转义；
> (2) `.skill` 扩展名**全小写是规范写法**（v3.11.11 起；此前为**首字母大写**的写法，因部分
> 系统做扩展名匹配时大小写敏感，统一小写更稳妥）——脚本内以
> `FMT_EXT` 常量为准，不要另行硬拼大小写。

**两种封装格式，内容完全相同**：

| 格式 | 说明 | 什么时候用 |
|---|---|---|
| `.skill` | **主格式**（默认与 `.zip` 同出）＝自定义头部 ＋ zip 负载。头部带产品名／技能 ID／版本／日期／条目数／负载 SHA-256 | 本地归档、版本对账；负载是裸 zip，Python `zipfile` 与 `unzip` 都能直接取内容 |
| `.zip` | 纯 ZIP，与开放平台（open.workbuddy.cn）实测口径一致（**官方收 zip、≤3 MB**） | **上传平台用这个**——`.skill` 是本技能自定义的封装，平台若不认就换 `.zip` |

> 需要哪种：`python scripts/pack.py <技能目录> --format skill|zip|both`（默认 `both`，两种都出）。

| 用法 | 是什么 | 适用 | 能出什么 |
|---|---|---|---|
| **全能用法** | 装整个包：通用库＋9 个内置行业库（可自建）＋脚本＋头标＋自检样本 | 原生技能平台（WorkBuddy / Claude Skills / Codex / Cursor 等）、能跑脚本 | 10 类交付物 × WORD/MD/Excel/HTML/PDF |
| **纯提示词用法** | 只取包内单个文件 `文档合规审查助手AI合同提示词版.md`（下称**提示词版**，不另出包） | 任何能设系统提示词的 AI：ChatGPT / Claude / DeepSeek / 豆包 / Kimi / 千问 / 元宝 / 文心 / Gemini | 只出 Markdown 文本：审查意见表、比对台账、红线文本版、修改后全文 |

**判断依据只有一条**：平台能不能跑 `scripts/` 里的 Python 脚本。能跑就装整包；只能把提示词贴进平台，就取提示词版。

**能力三档**（由平台条件决定，不是由包决定）：

| 档位 | 平台条件 | 可用能力 |
|---|---|---|
| **全功能档** | 能读写本机文件 **且** 能执行脚本 | 10 类交付物 × 5 格式、脱敏映射、两版比对、装机自检，全部可用 |
| **半功能档** | 能读写文件，**不能**执行脚本 | 可出审查意见与修改建议；Word/Excel/PDF 需在本机另跑 `make-docx.py` |
| **提示词档** | 纯对话，无文件/脚本能力 | 只走提示词版＋粘贴文本，出审查意见文本，无文件产物 |

规则优先级恒为 **私有库 > 行业库 > 通用库**（纯提示词版只走通用库＋可选行业口径，不读 `industries/` 文件）。

## 二、安装（五种方式，按平台选一种）

**先对号入座（速查）**——五种装法按平台条件选一种即可，后文是每种的详细步骤：

| 装法 | 一句话 | 平台 |
|---|---|---|
| **A 整包 zip 上传**（最省事） | 解压后第一层就是技能目录 `doc-compliance-review/`，**原样传 zip** 即可；要求「根目录须含 `SKILL.md`」的平台（千问云、Kimi）把里面那层**内容**重压一层再传 | WorkBuddy、Claude、千问云／千问办公、豆包工作、CodeBuddy、Kimi、有道龙虾 |
| **B 目录放置**（CLI / IDE） | 把**整个** `doc-compliance-review` 文件夹放进平台技能目录，重启生效 | Claude Code `~/.claude/skills/`、Codex `~/.codex/skills/`、Gemini CLI、Kimi Code CLI、Cursor `.cursor/skills/`、Copilot／VS Code `.github/skills/`、Qoder、Trae、其他 `~/.agents/skills/` |
| **C 纯提示词版** | 只取包内单文件「提示词版」，正文粘进系统提示词／智能体人设 | 任意能设系统提示词的 AI |
| **D 纯对话**（临时） | 把提示词版正文贴进第一轮对话，会话结束即失效 | 任意对话式 AI |
| **E 选在哪儿跑** | 桌面版本机 ／ 企业版 VPC ／ 自有 IDC；要全文不出域只能改**模型层**（接本地模型如 Ollama） | 组织级部署、信创与国产化场景 |

> **架构分层**：稳定层（`SKILL.md` 骨架）、可动层（core 规则 ID 管理）、可增删层（industries/private 整包增删）。
> **装完先做一件事**：跑一次 `python scripts/smoke-test.py` 验证（**默认快速档**，约 40 秒）。
> 依赖装在标准位置时**什么都不用填**——包内 `config.json` 的 `tools` 段是空的，脚本按 PATH 自动找；
> 若冒烟报缺某项，再跑 `python scripts/detect-tools.py --write` 写入本机路径（见第三节）。
> **工作目录也不用填**——默认 `auto` 自动探测。

### 2.1 方式 A：整包 zip 直接上传（最省事，优先试这个）

本包 zip **解压后第一层就是技能目录 `doc-compliance-review/`**，包内**恰好一份 `SKILL.md`**；体积**以出包产物实测为准**（v3.11.11 实测约 **1.49 MB**——**每次出包都会变，故此数不写死**，写死的版本早晚会漂），低于平台上限 **3 MB**：

- **开放平台（open.workbuddy.cn）与多数平台的上传入口**：**原样上传本 zip**，不必改结构；
- **要求「根目录须含 `SKILL.md`」的平台**（如千问云、Kimi）：把里面那层 `doc-compliance-review/` 的**内容**重新压一层 zip 再传（**不要**连带外面的目录名）。

| 平台 | 入口 | 要求与说明 |
|---|---|---|
| **Claude**（claude.ai / Desktop / Cowork） | 设置 → 自定义 → 技能 →「+ 创建技能」→「上传技能」 | 官方口径：把技能文件夹打成 ZIP 上传；装好后打开开关 |
| **千问云**（阿里云百炼·智能体平台） | 控制台 技能 → 自定义 Skill → 上传 zip | 官方口径：**zip ≤ 10 MB、根目录须含 SKILL.md**；上传后系统审查，变 active 才可挂载 |
| **千问办公** | 扩展 → 技能 → 右上角「+ 添加」→ 拖入 zip | 接受 zip 或直接拖单个 `SKILL.md`；技能落在 `~/.qwenworkcn/skills/` |
| **WorkBuddy**（本平台） | 技能页 →「+ 添加技能」→「上传技能」 | 文件夹或 zip 均可；也可把 zip 拖进对话说「导入技能」 |
| **豆包工作**（电脑端） | 侧栏「技能·连接器·伙伴」→ 新建 →「上传技能」 | 压缩包／文件夹／文件均可，**须含 SKILL.md**；须在「工作」模式，普通对话窗口不识别 |
| **CodeBuddy**（腾讯） | 技能 →「导入技能」，或把技能文件夹拖入窗口 | 目录形态 `.codebuddy/skills/<技能名>/SKILL.md` |
| **Kimi**（开放平台 platform.moonshot.cn） | 技能 → 创建自定义技能 → 提交 zip | **包内必须恰好一个 `SKILL.md`**，多一个或少一个都报 400 |
| **有道龙虾** | 把 zip 拖入对话并说「导入技能」 | 已实测可用 |

#### A-1 Kimi 分步部署（两条路，看你用哪个）

**路 1：Kimi 开放平台／云端智能体（platform.moonshot.cn，上传 zip）**

1. 进入控制台的技能页，创建自定义技能，以 `multipart/form-data` 提交本包 zip（也可提交 `.skill` 二进制包）；
2. 平台读取 `SKILL.md` frontmatter 里的 `name` 与 `description` 作为技能元信息；
3. 创建成功后**保存返回的 `skill.id`**，在智能体的 `skills` 数组里引用它（`version` 可填 `"latest"`）；
4. 调用方式：聊天框打 `/` 选技能，或由 Agent 依据 `description` 自动触发。

> **三条硬约束（踩了会直接失败）**：
> 1. 包内**必须恰好包含一个 `SKILL.md`** —— 缺了或出现第二个都会 400 报错。本包正好一个，**切勿再把提示词版改名成 `SKILL.md` 塞进去**。
> 2. 自定义技能**创建后不可修改**，修订＝归档旧的 → 用新包创建新技能 → 在智能体里更新引用。
> 3. 同一智能体内不得重复引用同一 `skill_id`，也不得挂两个同名技能。

**路 2：Kimi Code CLI（本机命令行，走目录）**

解压后按方式 B 放入 `~/.kimi/skills/`（用户级）或 `.agents/skills/`（项目级）即可，属**全功能档**——脚本在本机跑，需先装好 Python 依赖与 LibreOffice 等（见第四节）。

> **能力档位怎么判**：Kimi Code CLI 在本机执行 → 全功能档；云端 Agent 虽有执行环境，但 LibreOffice、Tesseract 等外部工具未必预装 → 多数落到**半功能档**。上传后先丢一份 `.docx` 试跑，看它能否直接吐出文件产物即可判定。

#### A-2 豆包工作分步部署（电脑端，一步一步走）

> 前提：**必须用电脑端豆包**，手机版没有入口；且要切到「工作」模式，普通对话窗口不识别技能文件。

1. 打开豆包 PC 客户端，左上角把「对话」切到**「工作」**模式（页面会刷新进入任务界面）；
2. 左侧栏点**「技能 · 连接器 · 伙伴」**，进入技能中心；
3. 右上角 **「+ 新建」→「上传技能」**；
4. 把本包的 **zip 直接拖进上传窗口**（**不要解压**，系统自动解析），或手动选择文件夹／文件；
5. 进度走完提示安装成功后，回到**「我的技能」**，确认该技能右侧的**启用开关是打开的**（未启用则不会生效）；
6. 使用：新建一个工作任务 → 输入框下方找到**「技能」选择器** → 勾选「文档合规审查助手AI合同」→ 输入审查指令。执行中出现「正在加载……技能」即说明已成功调用。

> **两个高频踩坑**：
> 1. **拖错位置**——拖到正中间的聊天输入框，豆包只会当成「已上传文档」；正确做法是拖进技能列表区域／上传窗口，成功后会弹「导入技能」的独立确认。
> 2. **导入了但没启用**——豆包允许同时装多个技能，部分默认未启用，须手动打开开关。

> **能力档位：按半功能档预期使用。** 豆包的技能机制以 `SKILL.md` 作指令驱动，第三方实证描述为「Skill 的本质是配置文本，不是可执行程序」，即 **`scripts/` 下的 Python 大概率不会被执行**。因此：上传整包依然有价值（拿到完整审查指令与规则口径），但**拿不到 Word/Excel/PDF 文件产物**；需要文件时，要么在本机另跑 `make-docx.py`，要么改用方式 C 的纯提示词版出 Markdown 再自行粘回 Word。
> 该判断依据为第三方教程实证而非厂商官方文档，请以你本机实测为准。

### 2.2 方式 B：原生技能目录（CLI / IDE 类）

1. 解压发布包（`.zip` 直接解压；`.skill` 同样可直接用解压软件打开，或改名为 `.zip` 再解压）；
2. **解压出来就是一个名为 `doc-compliance-review` 的文件夹**（包已按此结构打包，**不用自己再建一层、也不用把文件散着装进去**）；
3. 把这个 `doc-compliance-review` 文件夹放入下表的技能目录，重启平台或刷新技能列表，技能名显示为「文档合规审查助手AI合同」即为成功；
4. **部署后第一件事**：跑一次 `python scripts/smoke-test.py` 验证（默认快速档）。包内 `config.json` 的 `tools` 段**留空即可按 PATH 自动探测**；若冒烟报缺某项，再跑 `detect-tools.py --write` 写入本机路径（见第三节；工作目录默认自动探测，不用填）。

### 2.3 方式 C：纯提示词版（任意 AI 平台，最通用的兜底）

从发布包里取出**提示词版**（文件名 `文档合规审查助手AI合同提示词版.md`，它就在 `doc-compliance-review/` 目录下），把它的正文（从「你是一名资深企业法务…」到文件末尾）作为**系统提示词 / 自定义指令 / 智能体人设 / Custom GPT Instructions** 粘贴进去，再上传或粘贴文档全文即可。

**不需要安装任何东西、不执行脚本、不产出文件**，输出是 Markdown 文本。

四条落地要点：
1. **长文档分批**：按条款分批并声明「共 N 批，这是第 1 批」，逐批出意见后请它汇总总表；一次丢入超长全文会漏条。
2. **字数上限**（Custom GPT、部分智能体平台）：优先保留安全节、性质识别、风险分级、审查清单、输出格式，说明与示例可删。
3. **能出**：审查意见报告（Markdown 表）、两版比对台账、新旧条款对照、红线文本版（`<ins>/<del>` 或 `~~删除~~`＋`**新增**`）、修改后全文（可粘回 Word）。
4. **出不了**：Word 修订痕迹版、批注版、脱敏件、Excel/PDF —— 这些要用方式 A/B 的整包形态。

### 2.4 方式 D：纯对话平台（临时用一次）

把提示词版正文直接贴进第一轮对话作为指令，随后贴入待审文档全文。适合临时使用，会话结束即失效。

> 本技能遵循 **Agent Skills 开放标准**（`SKILL.md` ＋ 可选 `scripts/`、`references/`、`assets/`，规范见 agentskills.io），上表平台读的都是同一份 `SKILL.md`，**无需为不同平台改文件**。唯一差别在**能力档位**（见第一节三档表）。

### 2.5 方式 E：云端形态与私有部署（选在哪儿跑）

前四种方式回答的是"装进哪个平台"，这一种回答的是"**在哪儿跑**"——云端、企业内网，还是本机不出网。若你只在普通桌面版上用，跳过本节即可。

**E1 · 先分清三层——"私有"到哪一层，决定了数据出不出得去**

| 层 | 能否私有 | 依据 |
|---|---|---|
| **技能脚本层** | **天然私有** | **凡接触文档的脚本零出网路径**：提取、清洗、脱敏、生成交付物**全部可离线完成**；会联网的只有**"检查更新"**（只读公开清单、默认关，见 8.1）与**"法规库失效巡检"**（不联网做不成，须显式跑、且不在审查链路上）——二者都**不接触、不上传文档** |
| **模型层** | **取决于你接的是哪个模型** | 这是**唯一的出域点**——审查必须把文档全文读进模型上下文（架构决定，非本技能可控） |
| **平台层** | 取决于形态 | 桌面版本机运行 ／ 企业版 VPC 或自有 IDC |

> **一条最容易搞反的认知**：把技能装在本机、脚本零联网，只保证**处理环节**不出域；**只要接的是云端模型，文档全文照样会进模型上下文**。所以「技能支持私有部署」和「数据不出域」是两件事，后者由**模型层 + 平台是否用于训练**共同决定。

**E2 · 云端形态（企业版三档）**

依据腾讯云官方文档（cloud.tencent.com/document/product/1831/134332）：

| 版本 | 部署方式 | 数据边界 | 门槛 |
|---|---|---|---|
| SaaS 企业版（旗舰版） | 腾讯云**共享 VPC** | 云上共享环境 | 1 人起，198 元/人/月 |
| 专有云企业版（专享版） | 腾讯云**专享 VPC** | 独立区域，算力与公网及其他 VPC 隔离 | 100 人起，316 元/人/月 |
| **私有化企业版** | **企业私有化，客户自有 IDC** | **支持完全离线部署、支持国产化显卡** | **需自有 GPU 卡资源**，售前咨询 |

> **务必知情**：官方公开文档**未列明企业版是否支持上传自定义技能或同步技能目录**。技能本质是本机的目录资产，**不存在"把技能单独部署到云端"这个动作**——它跟随客户端或企业版环境走。若你要在企业版里用本技能，**请先向腾讯云确认自定义技能的支持情况**，不要假定与桌面版一致。

**E3 · 真正的私有部署抓手：接本地模型（Ollama）**

WorkBuddy 官方文档载明：设置 → 模型 → 自定义模型，支持 Provider Presets／Custom API／**Local Deployment (Ollama)**／Custom Protocol。Ollama 监听 `localhost:11474` 并暴露 **OpenAI 兼容接口**，可直连。官方列举的用途正是：**数据隐私与本地合规**（内容与对话不出本机）、**零成本**、**离线可用**（隔离网机器）。

**落地四步**

1. 安装 Ollama，拉取模型：`ollama pull <模型名>`；
2. 平台 → 设置 → 模型 → 添加自定义模型 → 选择 Ollama／本地 → 填 `http://localhost:11474`；
3. 按方式 A 或 B 安装本技能；
4. 跑 `python scripts/smoke-test.py` 验证脚本链路（这一层与所用模型无关，应 248 项全 PASS；**默认即快速档**，约 40 秒）。

> **务必知情的代价**：本地小模型的**长文档理解与推理能力弱于云端大模型**，合同审查恰恰是重推理、长上下文任务。建议 **32B 以上**并配合**分批审查**；关键合同仍应人工复核——本技能本就定位为辅助，不替代律师判断。

> **私密到什么程度、怎么选组合**（本机不出网／企业内网／先脱敏再交云端）属**数据安全口径**，不是安装步骤——见本教程「十五、安全与离线」，或 `README.md`「二、数据安全保障」。

## 三、首次配置：改 `scripts/config.json`

**所有本机路径都改这个文件，不要改脚本源码。** 命令行参数（`--base`/`--in`/`--out`/`--ts` 等）优先级高于本文件。留空的项按内置默认值或 PATH 回退。

> **随包的 `tools` 段本就是空的**（发布包不带任何人的本机路径）。也就是说：装完依赖后
> **通常什么都不用填**——脚本按 PATH 里的命令名自动找。**只有**在冒烟报告某项缺失、
> 或工具装在非标准位置时，才跑一次 `detect-tools.py --write` 把路径写进来（见 3.2）。

| 段 | 字段 | 说明 |
|---|---|---|
| `tools` | `soffice` | LibreOffice 主程序路径（老格式转文本、docx 生成、PDF 导出） |
| `tools` | `pdftotext` / `pdftoppm` | Poppler 两个可执行文件（PDF 取字、扫描件转图） |
| `tools` | `tesseract` / `tessdata` | OCR 主程序与语言包目录（中文需 `chi_sim`） |
| `workdir` | `base_dir` | 默认工作根目录，其下自动建 `输入`／`输出`。**默认 `auto`（自动探测，无需填写）**：推荐盘 `D:\文档合规审查报告` → 文档库 `~/Documents\文档合规审查报告` → 用户目录 → 临时目录，前一档不可用自动顺延 |
| `workdir` | `in_dir` / `out_dir` | 留空即用 `base_dir` 下的默认子目录 |
| `render` | `pdf_export` / `pdf_timeout_sec` | 是否导出 PDF、转换超时秒数 |
| `privacy` | `fulltext_gate` | 读全文进模型前是否先问密级（**建议保持 `true`**） |
| `privacy` | `on_confidential` | 涉密时动作：`local_only`（默认，走纯本地）／`ask` |
| `output` | `per_source_subdir` | 交付物是否按文档名自动分子目录（**防多客户混放，建议 `true`**） |
| `output` | `harden_acl` | 收紧输出目录访问控制，需显式运行 `scripts/harden-dir.py` 才生效 |

改动后无需重启，下次运行即生效。

### 3.1 工作目录：不用写死盘符

`base_dir` 默认 `auto`，按候选链自动探测，**没有 D 盘的机器也能直接跑**（自动顺延到文档库或用户目录）。候选链自上而下，前一档不可用自动顺延到下一档，**因此换机、无 D 盘、无写入权限都不会因路径写死而失败**：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `DOC_REVIEW_BASE` | 临时覆盖，优先级最高（批处理 / 临时换位置） |
| 2 | `config.json` 的绝对路径 | 自定义固定位置（`set-workdir.py --set` 写入） |
| 3 | 推荐盘 `D:\文档合规审查报告` | 有 D 盘即用，**无 D 盘自动跳过** |
| 4 | 文档库 `~/Documents/文档合规审查报告` | 跟随系统的文档库位置 |
| 5 | 用户目录 `~/文档合规审查报告` | |
| 6 | 系统临时目录下的同名目录 | 保底，保证一定能落地 |

目录下自动建 `输入` / `输出` 两个子目录。想换位置不必手改 json：

```bash
python scripts/set-workdir.py                        # 查看当前落在哪儿 + 全部候选（含可用性）
python scripts/set-workdir.py --set E:/我的审查报告   # 改为自定义位置（不存在则创建）
python scripts/set-workdir.py --auto                 # 恢复自动探测
python scripts/set-workdir.py --create               # 立即建好工作根目录与「输入」「输出」
python scripts/set-workdir.py --path                 # 只打印路径（供批处理取值）
```

临时换个位置（不改配置）：设环境变量 `DOC_REVIEW_BASE`，优先级高于 `config.json`。

### 3.2 工具路径：一条命令自动探测

手工抄 LibreOffice／Poppler／Tesseract 的安装路径是装机最大摩擦。装完依赖后跑：

```bash
python scripts/detect-tools.py                 # 查看探测结果（不改动任何文件）
python scripts/detect-tools.py --write         # 写入**本机覆盖层** config.local.json（推荐）
python scripts/detect-tools.py --path soffice  # 只打印某一项
```

> **不配也能用，配了才优先**：`tools` 留空时脚本按 PATH 自动找命令，**不用填任何东西**；
> 填了绝对路径则优先用它，路径失效时又自动退回 PATH，**不算错误**。想固化路径就跑 `--write`。
>
> **写进哪里很重要**：`--write` 默认写入 `scripts/config.local.json`——**本机专属，
> 不进发布包、也不随升级分发**。好处是整包拷给别人仍是干净的默认值，
> 别人升级也不会顶掉你的本机设置。要把整包连同你的路径一起拷走，才加 `--write-config`
> （写回 `scripts/config.json`）。删掉 `config.local.json` 即彻底回到自动探测。

探测顺序：**常见安装位置（含版本目录通配）→ PATH 中的同名命令**；写回时**只覆盖探测到的项**，未探测到的保持原值（不会把已填好的路径清空）。缺 LibreOffice 会提示其影响并以退出码 1 结束。

**缺什么就让它告诉你装什么**（只给命令、不代装）：

```bash
python scripts/detect-tools.py                                    # 外部工具 ＋ Python 环境（版本／python-docx／openpyxl／Pillow）
python scripts/detect-tools.py --install-guide                     # 打印**缺失项**的分平台安装命令
python scripts/detect-tools.py --install-guide --out install-deps.bat  # 写成脚本文件，自己核对后再运行
```

- `--install-guide` 按当前平台给出 winget／choco／scoop（Windows）、brew（macOS）、apt／dnf／pacman（Linux）与 pip 命令，并提示 Tesseract 的**中文语言包**怎么装；脚本自身**不联网、不自动安装**——装包要访问网络，这一步留在人手里。
- 依赖齐全时该命令只回一句「依赖齐全，无需安装」，不生成文件。
- 装完回到技能目录跑 `detect-tools.py --write && smoke-test.py` 收尾（冒烟默认即快速档）。

### 3.3 自检：全量档与快速档

```bash
python scripts/smoke-test.py            # 快速档（默认，248 项，约 40 秒）：日常改动后跑这个
python scripts/smoke-test.py --full     # 全量档（248 项，约 1 分钟）：装机验收、发版前跑这个
                                        # （--fast 保留为兼容旧写法，与裸跑等价）
python scripts/check.py                 # 结构/字段/规则ID/基线/配置/安全自检
python scripts/rule-baseline.py         # 规则库改动比对（改规则必跑；--update 刷新基线）
```

**默认就是快速档**（不必加参数）：跳过 PDF 导出与 OCR 等耗时项，**这些项记 SKIP 而非 FAIL，总项数不变**，便于与历史报告对齐。要真正跑这些耗时项，用 `--full` 全量档。`--fast` 作为旧写法保留，效果与裸跑相同。

## 四、环境依赖（按必要性分三档）

| 功能 | 依赖 | 必要性 |
|---|---|---|
| 老格式转文本（`.doc`/`.wps`/`.rtf`/`.odt`） | LibreOffice（无免费可靠平替） | **必需** |
| `.docx` 转文本 | **python-docx 直读（默认，约 0.02 s/份，零外部依赖）**；直读为空才回退 LibreOffice | 无需 |
| 生成 `.docx` 交付物 | Python `python-docx`（≥1.2 支持批注） | 必需 |
| PDF 导出 | LibreOffice（**缺失时自动跳过**，不阻断主流程） | 推荐 |
| PDF 文字提取 | Poppler(pdftotext) | 推荐 |
| PDF 转图 / 图像处理 | Poppler(pdftoppm) 或 ImageMagick | 推荐 |
| 扫描件/图片 OCR | Tesseract(chi_sim) 或 PaddleOCR | 推荐 |
| 交付物 Excel 导出 | Python `openpyxl` | 推荐（缺失仅跳过 xlsx） |
| 头标绘制（仅在重画 `assets` 时） | Python `Pillow` | 可选 |

**一句话**：只审 `.docx` 的话，**不装 LibreOffice 也能跑**；要处理老格式或扫描件才需要补齐依赖。

**缺 LibreOffice 时的两条降级**（按影响面从大到小）：

1. **PDF 导出**——自动跳过并在终端打印提示，其余格式（docx / md / Excel / html）照常产出，不阻断主流程；也可在 `config.json` 设 `render.pdf_export=false` 主动关闭。
2. **老格式 `.doc`/`.wps`/`.rtf`/`.odt`**——**没有可靠免费平替**（它们是 OLE 复合文档，python-docx 打不开），只能装 LibreOffice，或请对方另存为 `.docx`／直接把文本粘贴进来审查。日志会明确写出"该格式未能直读，需转换器"，**不会静默产出空文本**。

> **`.docx` 类默认走直读，不走转换器**：`.docx`/`.dotx`/`.docm`/`.dotm` 由 `python-docx` 直读（段落 ＋ 表格文本），**约 0.02 s/份**；走 LibreOffice 转换约 9 s/份，**两者产出文本一致**（归一化后逐字相同），故默认取快的一条：**直读为空才回退**转换。需要对齐旧产出文本或排查直读差异时，加 `--force-convert` 强制走转换器。
>
> **工具路径不再写死在脚本里**：脚本内与随包的 `config.json`（`tools` 段）**都不含任何本机路径**；
> 未配置或路径不存在时自动回退 PATH 命令名（`soffice`/`pdftotext`/`pdftoppm`/`tesseract`），
> 因此 macOS/Linux 同样可用。本机专属设定一律落在 `config.local.json`，
> 加载顺序为 `config.json` → `config.local.json`（后者覆盖前者），详见 3.2。

下载地址（各取官网即可，国内下载慢时改用高校镜像站加速——清华 `mirrors.tuna.tsinghua.edu.cn`、中科大 `mirrors.ustc.edu.cn`）：

- **LibreOffice**（必需）https://www.libreoffice.org/download/
- **Poppler for Windows**（`pdftotext`/`pdftoppm`）https://github.com/oschwartz10612/poppler-windows/releases
- **Tesseract**（Windows 版，页面内提供 chi_sim 中文语言包）https://github.com/UB-Mannheim/tesseract/wiki
- **ImageMagick** https://imagemagick.org/script/download.php

PaddleOCR、Python 按需到各自官网下载。装完可用 `python scripts/check.py` 验证。

安装要点：Windows 优先 `winget` 或官方安装包静默安装（`.msi`→`msiexec /i /qn`；`.exe`→`/S`），绿色包解压后将 `bin` 加入 PATH；macOS 用 `brew`，Linux 用 `apt/dnf`。**PATH 变更需重启应用/终端生效**，未重启用绝对路径。无依赖环境时可直接**粘贴文档文本**审查（跳过预处理脚本）。

## 五、装机自检

命令见 **3.3 自检**。共 **248 项**（依赖 → 预处理 → 真实文件链路 → 脱敏 → 比对 → 降级通道 → 交付物 → 内容自检）。**全 PASS 即可投产**。

## 七、升级与卸载

### 7.1 用户怎么知道有新版（检查更新）

**默认不会自己联网**（`config.json` 的 `update.check_online_by_default` 出厂为 `false`）——要不要查由你开口。下面第一条是"查这一次"，第二条是静默检查（默认配置下零请求、零输出）：

```bash
# 显式在线检查：显示 当前版 → 最新版、更新内容、下载指引
python scripts/version.py --check-online

# 静默检查（会话开头悄悄跑一次）：无新版不输出；有新版才提示
python scripts/version.py --notice
```

**有新版时会看到什么**（示例）：

```
[version] **有新版可用：当前 v3.11.11 → 最新 v3.12.0**（2026-10-20 发布）
[version] 一句话：新增某功能
[version] 新版更新了哪些内容：
           · 新增某功能
           · 修某缺陷
[version] **要不要更新由你定**——本工具只提示，绝不自动升级，也不会替你下载。
[version] 愿意更新的话，按三步走：
[version]   第一步 · 打开下载页：<下载页地址>
[version]   第二步 · 下载到本机（浏览器里下，地址与进度都看得见）
[version]   第三步 · 装上去（先预演、确认无误再执行）：见 7.3
```

**联网边界（要紧）**：检查更新**只读一份公开的版本清单，不上传任何使用者信息**；离线、连不上、
或未配置时**静默降级**（退回本地源；都不可用就一个字都不输出，**不报错、不卡住**）。
**想永久开启在线检查**：把 `scripts/config.json` 的 `update.check_online_by_default` 设为 `true`。
**想彻底断开**：把 `update.manifest_url` 留空，退回纯本地模式（用 `--watch` 登记本地目录或已下载的 zip 作更新源，见 7.2），**功能不降级**。

### 7.2 新版包从哪来：两种方式，随你选

| 方式 | 怎么拿到包 | 适合 |
|---|---|---|
| **本地方式** | 直接用**本机目录**或**已下载到本机的 zip**（U 盘、内网共享、发布目录） | 同机、内网、离网环境 |
| **联网方式** | 你**自己**用浏览器从**下载页**（见 7.1 提示的地址）**下载**到本机，再把**下载好的文件**交给工具 | 手边没现成包，需要从网上取 |

> **要紧**：**下载这一步永远由你来**——工具只给下载指引，**从不自动下载、从不自动安装**。
> 下载放在浏览器里**地址可见、进度可见、随时可中断**。两条路径在工具侧**完全一样**：
> 接到的都是一个本地目录或本地 zip，因此走**同一套**校验／预演／备份／升级，保护规则不打折。

### 7.3 升级命令（先预演、再执行）

用 `version.py` 走升级更安全——**装这一步在本地完成**，先预演、再执行：

```bash
# —— 看清自己装的是哪一版 ——
python scripts/version.py                                            # 版本身份证（版本／脚本数／规则数／行业库数）

# —— 有没有新版：登记一次更新源，以后不必手打路径 ——
python scripts/version.py --watch <更新源目录或 zip>                    # 登记更新源（本机记住路径）
python scripts/version.py --notice                                    # 静默检查：无新版一个字都不输出；有新版才提示
python scripts/version.py --source                                    # 看登记的是哪个源、源版本更高还是更低
python scripts/version.py --check                                     # 与登记源比对（也可 --check <指定的源>）
python scripts/version.py --changelog <源>                             # 摘出「当前版本 → 源版本」之间的沿革条目
python scripts/version.py --dismiss 3.7.0                             # 不想再看到某版本的提醒时忽略它
python scripts/version.py --unwatch                                   # 取消登记，不再提示新版本

# —— 注：本技能不提供历史版本沿革（沿革与 history 都不随包分发）——
#    能查的只有「当前是哪一版、这一版改了什么」；问历史版本会如实回答「不提供」

# —— 升级：先预演，确认后才真正装 ——
python scripts/version.py --upgrade <源> --target <安装目录>             # 预演：列出覆盖/新增/保留，不动文件
python scripts/version.py --upgrade <源> --target <安装目录> --apply      # 执行：先整目录备份，再覆盖
```

> 也可以直接对本技能说 **「技能版本」**（看版本身份证）／ **「技能更新」**（比对有无新版）／
> **「技能升级」**（预演后确认升级）——三个触发词都归这条路。

- **更新源由使用者自己给**——本地目录、内网共享、发布目录、未解开的 zip 均可；**联网方式**则是你先用浏览器把包下到本机，再把文件交给工具。因此「检测更新」**不需要也不会联网**；判定依据是两侧 `SKILL.md` frontmatter 的 `version`。
- **只提示，绝不自动升级**：`--notice` 与 `--check` 都只读不写。**发现新版就替使用者装上，是明确排除的行为**——跨版本可能改变审查口径与产出形态，什么时候切必须由人判断；手上有正在进行的审查任务时，建议做完再升。
- **升级必须先预演**：不带 `--apply` 就是 dry-run，一个字节都不动；确认列出的事项都接受后才加 `--apply`。
- **升级保护**：`private/`（脱敏词表、映射表）**永不覆盖**；`scripts/config.json`（本机工作目录等）**默认保留**，需 `--overwrite-config` 才覆盖；目标里有、源里没有的文件**一律保留并列出，不删除**。**本机工具路径不受升级影响**——它在 `config.local.json` 里，新版发布包压根不含此文件，无从覆盖。
- **升级前自动备份**：整目录备份到 `<安装目录>_bak-V<旧版本>-<时间戳>`，与安装目录同级。升级后按提示跑 `check.py` 与 `smoke-test.py`（默认快速档；装机验收用 `--full`）。

手动升级亦可：解压新版，**整个目录覆盖**原位置；`config.json` 会被新版覆盖，**升级前先备份该文件**，装完比对字段再跑一次自检。不过跑过 `detect-tools.py --write` 的话，本机工具路径在 `config.local.json` 中、**不会被覆盖，也不必备份**。
- **卸载**：删除技能目录即可。另需清两处本机数据——输出目录（`base_dir`，含交付物与 `.clean.txt`）与脱敏映射表（默认 `~/.dcr-maps/`）。**映射表等于回填钥匙，卸载时一并处理**。

## 八、开始审查：两个必过的关口

### 8.1 先问一句：这份文件能不能给 AI 看（默认每次先问）

审查需要把**全文读入模型上下文**——说白了就是**把整份文件交给 AI 看一遍**，这是一次数据出域。所以读全文前会先问一句：

> 本文件是否涉密/敏感（商业秘密、未公开交易、个人信息批量、涉密等级文件）？

- 答**否** → 正常审查，并在读取时说明「已将全文提交模型处理」；
- 答**是**，或明确要求「不上传/不外发」 → **不读全文、不进模型**，改走纯本地链路 `python scripts/local-only.py <文件>`（本机提取清洗 → 本机正则脱敏，全程不联网、不调 AI）。

> **脱敏是伪名化，不是不可逆销毁**——即便已脱敏，外发前仍应自行评估。

**按私密程度选：三档组合**

| 组合 | 数据出域 | 适用 |
|---|---|---|
| **1. 桌面版 ＋ Ollama 本地模型 ＋ 本技能** | **全文不出本机** | 涉密件、客户敏感件、个人执业 |
| **2. 私有化企业版（自有 IDC，离线部署）** | 不出企业内网 | 组织级、信创与国产化要求 |
| **3. 先 `local-only.py` 脱敏 → 再交云端模型** | 只出**脱敏文本** | 无本地算力时的折中，性价比最高 |

- 组合 3. 的命令：`python scripts/local-only.py "D:\某合同.docx"` —— 纯本地提取 ＋ **10 类全脱**（证件号/电话/银行账号/邮箱/邮编/IM/统一社会信用代码/绝对金额/地址/人名），**不入模型、可断网**；再把脱敏件交给任意云端模型审查。
- 组合 1. 怎么装（接本地模型 Ollama）：见本教程 2.5。
- **别搞反**：技能装在本机、脚本零联网，只保证**处理环节**不出域；**只要接的是云端模型，全文照样进模型上下文**。组合 1、2 之所以私密，是因为**模型也在本地／内网**，与技能本身无关。

**「技能层联网边界」的实现机制**（上面"处理环节不出域"的技术依据）：

> **一句话**：**凡接触你的文档的脚本，全部纯本地、零出网路径**；
> 会联网的只有两类——**"检查更新"（只读公开清单、默认关）**与**"法规库失效巡检"（不联网做不成、须你显式跑）**。
> 二者都**只读公开内容、不上传任何信息**，且都随时可关。
> **口径是"文档出不出域"，不是"联不联网"**——联网本身不是风险，带着文档出去才是。

| 环节 | 联网？ | 具体做法 |
|---|---|---|
| **处理文档**（提取／清洗／脱敏／出件） | **不联网** | 全程纯本地；依赖仅 Python **标准库** ＋ `python-docx`／`openpyxl`／`Pillow` 等纯本地库 |
| **外部能力**（Office／PDF／OCR 转换） | **不联网** | LibreOffice／Poppler／Tesseract／ImageMagick 均为**本机命令行**调用，以 `subprocess` **列表参数**传入（无 `shell=True`） |
| **检查更新** | **会联网**（默认关，可关） | **只读**公开的版本清单，**只做 GET、不上传使用者信息**；离线／连不上**静默降级**、不报错不卡住 |
| **法规库失效巡检** | **会联网**（**须你显式跑**） | 只抓**公开法规页面**做条文比对，**不接触、不上传文档**；**不在审查链路上**（审查时用本地库）；抓不到就明示"没验成"，**绝不假报"验过了"** |
| **下载／安装新版** | **不联网** | 包由**你自己在浏览器下载**；工具只给下载指引，**从不自动下载、从不自动安装** |

**怎么关**：把 `scripts/config.json` 的 `update.manifest_url` 留空即关闭在线检查，退回纯本地模式（`--watch` 登记本地源）。**功能不降级。**

```bash
# 核验：除 version.py（联网仅用于读公开清单）外，其余脚本应无联网调用
python -c "import pathlib; ks=('requests','urllib','socket','http.client','aiohttp','httpx','curl','wget','Invoke-WebRequest','smtplib'); print([f.name for f in pathlib.Path('scripts').glob('*.py') if any(k in f.read_text(encoding='utf-8',errors='ignore') for k in ks)])"
```

### 8.2 文档性质识别（全库总闸）

合同与非合同**有交集但不等同**：非合同文件**不一定有对立当事人、不一定有我方立场、不一定涉及权利义务**，因此**不能直接套用合同审查框架**。

每次会先给出 AI 初判＋理由，请你确认或更正：

| 选项 | 含义 | 后续路径 |
|---|---|---|
| **1. 合同类** | 双方或多方合意，有给付与对待给付 | 通用清单 ＋ **合同八大核心条款** |
| **2. 非合同类** | 授权书/委托书/承诺函/担保函/告知书/声明/章程/制度/政策/通知/公告/纪要/说明/报告/招投标文件/SLA 等 | 通用清单 ＋ **非合同专项** ＋ **F 组** |
| **3. 混合型** | 合同正文＋非合同附件并存 | **按组成部分分区适用**，各部分标明性质 |
| **4. 请 AI 判定** | AI 给出最可能的性质与理由并标注假设 | 报告中显著标「文档性质为 AI 推定，请复核」 |

完整适配规则见 `core/01-general-risk-rules.md` **第 1 节**。

> **确不适用的维度会写明「不适用（原因：＿＿）」**，不留白、不硬套——这一点在审单方文件时尤其重要，请勿把它当成漏审。

## 九、完整流程（开场一张清单问完）

首次使用会在**读完文件名与首屏后**一次性列出全部待填项（涉密门 · 文件性质 · 加载库 · 我方身份 · 审查尺度 · 交付物与格式 · 审查人），**一次问完，之后一路跑到底不打断**。**选项一律能点就点**：单选给 radio、多选给 checkbox 并标「可多选」、附全选/清空；选项多时分组呈现（如加载库分「基础层／内置 9 个行业库／自定义」）。**不能点也能少打字**：`1,3,5`／`3-11`／`全`／`全-2`／`一、三`／`医药` 这些写法都认，`全默认` 一键盘，`同上` 沿用上次：

```
0.0  免责声明（同一对话内首次使用先输出全文）
1.0  开场一次问完（四小步，一次做完）
     1.0.1 涉密门：这份文件能不能给 AI 看（涉密/敏感？读全文前先问）
     1.0.2 开场清单：一张清单问完全部输入项
     1.0.3 作答方式与默认值（可回「全默认」；未填项按默认值执行）
     1.0.4 收口后不再发问（只允许回问审查人缺失与无法推断的分叉）
1.1  只要脱敏、不要审查（按需）
1.2  环境自检与部署
1.3  文档性质识别（AI 初判 → 你确认）
1.4  选择加载库（勾选框 · 多选 · 一次全部显示）
1.5  确定我方身份与立场
1.6  选择审查尺度（严苛 / 中性 / 宽松）
1.7  加载规则库（三层：通用 + 行业 + 私有）
1.8  默认兜底 → 进入工作流：逐条审查 → 三色分级 → 产出交付物（10 类 × 5 格式，审查人必填）→ 任务总结 → 收尾

（1.3–1.6 的询问已由 1.0.2 清单收口，清单填过即不再单独发问。）
```

**1.4 选择加载库**（一次列出全部可勾选项，**多选**；勾选项清单以 `SKILL.md` 1.4 为准，此处不复制）：

- 同时勾两个及以上行业库＝**多行业叠加**（主行业＋关联行业），不必另找入口；
- **不可用项照常列出但置灰**，不会静默隐藏；
- 冲突一律按 **私有库 > 行业库 > 通用库** 消解；无法消解的标 ★★★ 交人工。

**1.5 我方身份与立场**

- **合同类**：文档中当事人不一定写甲/乙方，也可能是卖方/买方、供货方/采购方、委托人/受托人，或直接写主体名称与简称。**直接回答你方的主体名称最稳妥**（如「我方是北京某某科技有限公司」）；文档用甲/乙方指代的，回「甲方」「乙方」即可。
- **非合同类**：**不会虚构甲/乙方**，改问身份——**作出方**（授权人／承诺人／发布方／用人单位）· **接收方**（被授权人／受益人／被告知人／员工）· **中立审查**（不代表任何一方，只评合法性与周延性）。
- **单方文件**：角色栏写「不适用（单方文件，无对立当事人）」，结论改用**取舍建议**（必改／建议改／可保留），不再用谈判口径。

**1.6 审查尺度**

| 尺度 | 适用 |
|---|---|
| 严苛 | 逐条零容忍、尽可能要求修改 —— 高价值/高风险重大文档 |
| **中性（默认）** | 常规实务尺度 —— 一般商务文档 |
| 宽松 | 只抓重大红线 —— 低风险/标准化常规文档 |

**风险三色分级**

★★★ 高（红）／ ★★ 中（橙）／ ★ 低（绿）。每条意见固定七要素：

```
条款定位 | 风险描述 | 评级 | 法律依据(附法条) | 修改建议（可直接采用的条款文本）
       | 优先级(必争/应争/可让) | 退让方案
```

修改建议写成**可直接替换/插入的条款正文**（含条号、可执行），不是方向性意见。

## 十一、交互口径（三条铁律）

1. **每个提问都有编号、能点就不打字**：全文提问一律带**全局流水号**（同一会话 Q1、Q2…连续递增、不复用），**选项本身也带号**（卡片写「1. 合同类」，与文字清单同形同号）；有交互控件必须弹单选/多选，无控件整块列全、**回数字即可**；只有审查人姓名、主体名称、金额、补充说明这类自由项才打字，题干会明写「此项须打字」（详见 SKILL 1.0.3 提问总纲）。
   **要是根本选不中呢**：回一句「选不中」就行——技能会**立刻改成一次一题**地问（11 题拆开，每题自带选项与默认值；已答过的不重问，回「默认」跳过、回「全默认」剩下全按默认）。**别在一个点不动的方框上反复试**，那不是您不会用。
2. **能多选的一律勾选框、一次全部显示**——加载库、交付物类型、文件格式都是如此，**不逐条追问、不折叠、不截断**；单选题有默认值（加载库＝通用版；我方身份＝合同类取文中首位当事人／非合同类取中立审查；尺度＝中性；地位＝均衡；性质＝请 AI 判定），回复「下一步／继续／默认／随便／都行」即取默认。
3. **可事后更正**：一句话更正并重跑，不必从头再来。

> **原稿修改是硬性要求**：修订类交付物（修订版／清洁版／红线版／脱敏版／照录版）**必须在原稿上改**；拿不到可编辑原稿（.docx）或脚本暂不支持时**自动降级**为样式档位重建，并在**文件名、文档属性、报告**三处显著标注「⚠ 降级：非原稿修改（原因）」——绝不静默重建、绝不冒充原稿修改。

## 十二、交付物（10 类 × 5 格式）

| 编号 | 类型 | 说明 |

| 1 | 修订版 | Word 原生修订痕迹（**首选**，可逐条接受/拒绝） |

| 4 | 红线修订格式版 | 删除线/下划线标出差异，不依赖 Word 修订功能 |
| 5 | 审查意见报告 | 逐条意见＋三色分级＋标准话术 |
| 6 | 原文脱敏版 | 10 类全脱，供对外出域 |
| 7 | 原文照录版 | 原样留存 |
| 8 | 文件比对报告 | **两份文件**的差异台账 |
| 9 | 新旧比对 | **同一文档**改前改后的左右对照 |
| 10 | 模板版 | **转模板 / 撰写模板**产出：占位符说明表 ＋ 模板正文 ＋ 可选条款区 ＋ 使用须知 |

格式：`docx` / `md` / `excel` / `html` / `pdf`（勾选框多选，一次全部显示）。

**HTML 网页浏览版**（新增第 5 种）：产出**单文件网页**——CSS/JS 全内联、**零外部资源**，断网可开、可直接转发给别人；带**顶部固定目录导航**（锚点服务端生成，浏览器禁 JS 也能跳转）、**点击标题折叠／展开条款**、右上角「**打印 / 存 PDF**」（`@media print` 已排 A4 版心并隐藏导航与按钮）；评级 ★/★★/★★★ 着色为**三色标签**（高红／中橙／低绿）。由 md 转换，**优先用 `markdown` 库、没装则自动降级内置转换器**（不报错、不阻断出件，想让语法覆盖更全就 `pip install markdown`）。

命名规则：`<源文件名>_<类型>_<审查人>_r<轮次>_<时间戳>.<ext>`，**审查人必填**。产物默认写入 `<工作根目录>\输出`，**按文档名自动建子目录**（防多客户混放）。

**排版保真（可选，半档 C）**：默认 10 类 Word 按审查规格重建，版式由样式档位决定（`--style contract`（默认）／`official`／`default`，只对 1、3、4、6、7 五类生效）。若手上有**原稿 `.docx`**，加 `--source-docx <原稿.docx>`（或 spec 里写 `source_docx`）即可升级保真：**3 修改后清洁版／6 原文脱敏版／7 原文照录版**改为「以原稿做底 ＋ 段落级替换文字」——不增删段落，**字体、字号、对齐、缩进、行距、页边距、页眉页脚、表格与图片全部沿用原稿**。修订类 1、4 与报告类 2、5、8、9、10 不走这条；原稿缺失或不是 `.docx` 时自动回退样式档位，不影响产出。

## 十三、脱敏的两条口径（不可混用）

| 场景 | 用的工具 | 脱敏范围 |
|---|---|---|
| **审查用**（文档留在本地、只进模型） | `desensitize.py` | **6 类**，保留统一社会信用代码、金额、地址、人名（否则没法审） |
| **对外出域**（要发给对方/上传外部平台） | `local-only.py` | **10 类全脱**，可纯本地、不联网、零 token |

**六类是哪六类**：证件号 ／ **电话** ／ 银行账号 ／ 邮箱 ／ 邮编 ／ **IM**。

> **为什么是"总类"**：座机与手机只是电话的两种写法，微信／钉钉／QQ／脸书／微博只是不同的即时通讯工具。
> 写法千变万化、工具年年新增，逐一枚举的清单必然挂一漏万——统一归成**电话**与 **IM** 两类后，
> 标签分别为 PHONE / IM，看得出这一项是什么、又拿不到值本身。**规则更少，漏网反而更少。**
>
> 同理，**证件号**也是总类：身份证／居住证／港澳通行证／台胞证／护照（含外国护照）／营业执照注册号／税号一视同仁。
>
> **识别方式**：电话可**裸值识别**（`13800138000`、`021-58888888`、`（010）62345678` 半角全角括号都认）；
> 邮编与 IM 需**带标签**才认（「邮编：」「微信：」「QQ号：」）——QQ 号是纯数字，裸值猜测必误伤订单号与批次号。

- **比例（30% 这类）不脱**；
- 映射表隔离存放在 `~/.dcr-maps/`，**不与源文件同目录**，可 `restore` 回填；
- **映射表等于回填钥匙，绝不随件外发**；
- Office/扫描件先过 `preprocess.py` 再脱敏。

## 十四、维护私有库与行业库（权限 · 备份 · 触发词）

三个库的处置权限不同，**动手前先看清楚**：

| 资源 | 能不能改 | 能不能删 | 能不能复制/导出/导入 | 能不能查看内容 |
|---|---|---|---|---|
| 通用库 `core/` | ✘（规则写死） | ✘ | ✘ | ✘ |
| 行业库 `industries/` | ✔ | **见下方条件 A** | ✔ | ✔ |
| 私有库 `private/` | ✔ | ✔ | ✔ | ✔ |

- **通用库是产品内核，只读**：想收紧或改写某条内核规则，用私有库以 `<规则ID>@private` 覆盖（优先级最高），**不要改 `core/`**。

**条件 A —— 行业库的删除分两种情况**（不是一刀切）：

| 行业库 | 能不能改 | 能不能删 |
|---|---|---|
| **初始内置 9 个**（`food` `hr` `manufacturing` `medical` `newenergy` `newmedia` `newretail` `pharma` `realestate`） | ✔ 修改／编辑／更新都可以 | ✘ **不可删除**（它随安装包分发，删了连升级都补不回来） |
| **你自建的行业库** | ✔ | ✔ **可以删**（自己的东西，留或删自定） |

想停用某个内置库，在加载库清单里**不勾选它**即可，不必删文件。拿不准某个库能不能删，跑一条命令就清楚：
`python scripts/guard.py check industries/<slug>-rules.md --op delete`（放行退 0、拒绝退 3）。

- **私有库是你自己的内控口径**，增删改、复制、导出都可以。
- **两个库都能导入导出**：换机器、给同事一份、或先导出备份再改——导出的是**库内容（规则文件）**，不含技能本体。`guard.py export <库>` ／ `guard.py import <库> <zip>`；导出前不必手动备份，**导入前会自动备份一份**，且**默认不覆盖同名文件**（要覆盖加 `--overwrite`）。初始内置行业库不接受外来文件顶替。

**维护子菜单**（进入维护私有库／行业库时先选动作，备份与回溯是其中两项）：新建规则 ／ 修改更新既有规则 ／ **备份** ／ **回溯** ／ 查看备份列表。前两项是写动作，**动手前必须先备份**，改坏了用回溯退回。

```powershell
python scripts/guard.py backup private        # 备份（动库前先做）
python scripts/guard.py backup industries
python scripts/guard.py list-backups          # 看已有备份（序号 1＝最新）
python scripts/guard.py restore private --pick 1      # 回溯到最新那份
python scripts/guard.py restore industries --pick 2   # 回溯到倒数第二份
python scripts/guard.py restore private --file <备份.zip>   # 直接指定某一份
python scripts/guard.py export private --out D:\私库.zip     # 导出库内容（换机器/给同事）
python scripts/guard.py import private D:\私库.zip           # 导入（导入前自动备份，默认不覆盖同名）
python scripts/guard.py policy                # 看权限矩阵
```

备份落在**隔离目录** `~/.dcr-backups/<库名>/`（环境变量 `DCR_BACKUP_DIR` 可整体改换），命名 `<库>-V<版本>-<时间>.zip`——**时间与版本都在名字里**，一眼认得出。**每库最多 5 份，满 5 份删最旧的再建**（循环覆盖），不会无限堆积。

**回溯的三条安全阀**：(1) 恢复前**先把当前状态自动备份一份**（文件名带 `-prerestore`），所以**任何一次回溯都还能再退回来**；(2) **默认只覆盖与补齐，不删**当前有而备份里没有的文件（避免误删后来新增的规则）——要严格还原成备份那一刻加 `--prune`（私有库照删；**行业库跳过初始内置 9 个库的文件**，只删自建部分）；(3) 权限按上表判定，**通用库不可回溯**。

**维护触发词****（不区分大小写，句中片段命中即算）——共 4 类，权威清单见 `permissions-and-libraries.md`「维护触发词」表**：
(1) **私有库维护／编辑／更新／新建** → 私有库向导；
(2) **行业库维护／编辑／更新／新建** → 行业库向导；
(3) **导出私有库／导出行业库／导出库** → `guard.py export`；
(4) **导入私有库／导入行业库／导入库** → `guard.py import`。
前四种说法是同一入口：新建＝库还没有，更新＝加新规则，编辑与维护＝改既有规则。（注：此处**按入口类别计数为 4 类**；早期版本误记为"8 个词条"，是把(5)(6)两类的等价说法相加、又漏了(7)(8)两类所致。）

**技能本体不外流**：不可查看、复制、导出技能内容与目录结构，也不可复制或导出技能包。**可看的只有五项**（版本沿革不对外提供）：

```powershell
python scripts/guard.py view readme        # README.md 手册
python scripts/guard.py view version       # 版本身份证（版本／脚本数／规则数）
python scripts/guard.py view license       # LICENSE.md 许可与免责
python scripts/guard.py view tutorial      # 安装使用教程
python scripts/guard.py view prompt        # 提示词版
```

自然语言同样受理：「看一下手册」「什么版本」「许可条款」「安装教程」「提示词版」。
