## 二、新分级体系（本设计的核心）

### 2.1 五个档位

> **档位（落到哪）与要求（该落哪）是两个维度**，勿混：
> 档位描述"本次产物实际是什么"，要求描述"该交付物被允许落在哪"。矩阵见 §2.2。

| 档位 | 代号 | 含义 | 谁能落到这里 |
|---|---|---|---|
| **原稿级** | `ORIGINAL` | 原稿字节即底稿，版式一字未动（文字除外） | 1/3/4/5 达标态；7 有原稿时的达标态 |
| **准原稿级 A** | `QUASI_A` | 有格式线索，按 §2.3 边界**尽量贴近**原稿版式重建 | 1/3/4/5/7 的降级态 |
| **准原稿级 B** | `QUASI_B` | 无任何格式线索，**纯模板重建** | 1/3/4/5/7 的降级态 |
| **内容保真** | `CONTENT_ONLY` | **只管内容对不对，不管版式** | **仅** 6 |
| **新建文档** | `NEWDOC` | 本就该新建，不适用版式保真 | **仅** 2/8/9/10（6 亦可） |

### 2.2 交付物 × 要求矩阵（**要求的唯一真源**，编号即勾选框序号）

| # | 交付物 | slug | 档位要求 | 允许落点 | 未达标是否触发退出码 3 |
|---|---|---|---|---|---|
| **1** | **修订版** | `tracked` | **原稿级（硬性）** | ORIGINAL ／ QUASI_A ／ QUASI_B | ✅ 落到 QUASI_* 即触发 |
| **2** | 审查意见报告 | `report` | **引文保真** | NEWDOC（版式）＋ 引文须逐字取自原稿 | ❌ 不触发 |
| **3** | **清洁版** | `clean` | **原稿级（硬性）** | ORIGINAL ／ QUASI_A ／ QUASI_B | ✅ 落到 QUASI_* 即触发 |
| **4** | 红线标记修订版 | `redline` | **原稿级（硬性）** | ORIGINAL ／ QUASI_A ／ QUASI_B | ✅ 落到 QUASI_* 即触发 |
| **5** | 审查意见批注版 | `reportc` | **原稿级（硬性）** | ORIGINAL ／ QUASI_A ／ QUASI_B | ✅ 落到 QUASI_* 即触发 |
| **6** | 原文脱敏版 | `masked` | **内容保真（已放宽）** | 任意档位均可（ORIGINAL ／ QUASI_* ／ NEWDOC） | ❌ 不触发 |
| **7** | 原文照录版 | `original` | **有原稿必须原稿级；无原稿可降准原稿级** | ORIGINAL ／ QUASI_A ／ QUASI_B | ✅ **仅当有可用原稿却落到 QUASI_*** |
| **8** | 文件比对报告 | `diff` | 新建 | NEWDOC | ❌ 不触发 |
| **9** | 新旧比对 | `compare` | 新建 | NEWDOC | ❌ 不触发 |
| **10** | 模板版 | `template` | 新建 | NEWDOC | ❌ 不触发 |

> 退出码 3 还须**同时**满足"传了 `--strict-fidelity-exit`"——本列只说"是否具备触发资格"，见 §3.4。

**分组说明（对应你给的排序规则）**

| 分组 | 编号 | 排序依据 |
|---|---|---|
| **默认两类**（使用频率最高） | 1、2 | 「使用频率优先」——修订版 + 审查意见报告是默认组合 |
| **保真类**（档位分组） | 3、4、5、6 | **清洁 → 红线 → 批注 → 脱敏**（按定稿 → 标痕 → 加注 → 去敏的推进次序） |
| **照录类** | 7 | 单独成组（准原稿级） |
| **新建类** | 8、9、10 | 比对与模板，天然新建 |

> **编号稳定性承诺（v3.27.0 起的硬约束）**
> 1–10 的序号自 v3.27.0 发布起**不再变动**。新增交付物一律取下一个空号（11、12…），**不得插队重排**。
> 理由：编号是 AI 与用户的通用语言（勾选框、`--types` 参数、报告正文都引用它），重排一次就要改全仓，
> 极易漏改（v3.26.16 那次重排即留有多处散落旧号）。**分组是文档侧的说明，不是编号的依据。**
>
> **v3.27.0 是本承诺生效前的最后一次重排**：保真类由「红线→批注→清洁→脱敏」改为「清洁→红线→批注→脱敏」，
> 故 **3/4/5 三个编号互换**（旧 3 红线→新 4；旧 4 批注→新 5；旧 5 清洁→新 3），6–10 不变。

> **相对 v3.26.19 的四处实质变化**（编号重排已见上条，此处不重复）
> ① **清洁版升为硬性原稿级**（现状静默降级、不打标记）—— 本次最实质的收紧
> ② **6 原文脱敏版放宽为「内容保真」**：不再要求原稿级，也不触发退出码 3。
>    理由：脱敏价值在**内容不外泄**，不在版式；客户常给扫描件/照片，硬要求原稿级会频繁误报
> ③ **7 明确为准原稿级**：有可用原稿时必须 ORIGINAL；拿不到才落 QUASI_A/B
> ④ **2 明确为引文保真**：报告独立成文（版式 NEWDOC），但**引用的原文必须逐字取自原稿**，
>    不得由模型凭记忆复述

### 2.3 QUASI_A 的边界（**已裁决：做到「页面 + 字体」层**）

#### 2.3.1 判据（必须可机械判定）

不能靠感觉分。判据：**本次是否拿到了可用于还原版式的结构化线索**。

| 来源 | 能拿到的线索 | 落到的档位 |
|---|---|---|
| 真 `.docx` / `.doc`（转换成功） | 全部（页边距、页眉页脚、样式、表格、图片） | `ORIGINAL` |
| `.doc` 转换失败（无 LibreOffice 等） | 无 | `QUASI_B` |
| PDF（**有文字层 + 可解析版面**） | 页面尺寸、页边距、文字块位置、字号 | `QUASI_A` |
| PDF（仅文字层，版面解析失败） | 仅文字流 | `QUASI_B` |
| 扫描件 PDF / 图片 / 拍照 | 仅 OCR 文字，无版面 | `QUASI_B` |
| 粘贴文本 | 无 | `QUASI_B` |
| 完全未提供原稿 | 无 | `QUASI_B` |

> **上表只定"档位"，不定"要不要出文件"**：即使落到 `QUASI_B`，1/3/4/5/7 仍**照出**（这正是"照出 + 强标注"的意思），
> 只有 2/8/9/10 这类本当新建的不受影响。**任何情况下都不因降级而拒绝产出。**

#### 2.3.2 贴近边界（**L2 封顶**）

| 层 | 内容 | 是否做 |
|---|---|---|
| **L1 页面层** | 页面尺寸（A4/Letter）、页边距（上下左右） | ✅ 做 |
| **L2 字体层** | 正文与标题的字体族、字号、行距 | ✅ 做 |
| **L3 结构层** | 表格边框、页眉页脚、段落编号、图文绕排 | ❌ **不做** |

**为什么不做到 L3**：PDF 里的表格边框与页眉页脚无法可靠反推（边框常是绘制的线条而非表格属性，
页眉页脚在 PDF 里只是"页面顶部的文字"，没有语义归属）。**硬猜出来的结果比不猜更糟**——
看起来"还原了"，实际把正文错认成页眉，或把一段文字塞进假表格。

**判定口径**：L1+L2 全部成功映射 → `QUASI_A`；任一失败 → `QUASI_B`。**不部分降级、不做"半 A 半 B"**。

## 三、档位如何外显（四处，缺一不可）

### 3.1 文件名

```
现状：  合同_修改后清洁版_张三_r1_20261103-1430.docx
新：     合同_清洁版_张三_r1_20261103-1430.docx                ← ORIGINAL（不加标记）
        合同_清洁版-准原稿A_张三_r1_20261103-1430.docx         ← QUASI_A
        合同_清洁版-准原稿B_张三_r1_20261103-1430.docx         ← QUASI_B

        合同_修订版_张三_r1_20261103-1430.docx                 ← ORIGINAL
        合同_修订版-准原稿B_张三_r1_20261103-1430.docx         ← QUASI_B

        合同_原文脱敏版_张三_r1_20261103-1430.docx             ← CONTENT_ONLY（不标档位）
```

> 弃用旧的 `-降级` / `-降级-部分`：含义太糊，「降级」降到了哪里说不清。新标记直接说出档位。
> **`CONTENT_ONLY` 不打标记**：脱敏版对版式本就没有要求，标一个"准原稿"会让使用者误以为版式打了折。

### 3.2 文档属性（Core Properties）

写入三个**自定义属性**（`docProps/custom.xml`，用 `python-docx` 的 `custom_properties` 写入），
另在文档正文**不加**任何可见文字——属性是给机器与"文件属性"面板看的，不污染正文。

```
dcr-fidelity-tier:      QUASI_A
dcr-fidelity-reason:    PDF 有文字层与版面信息，已按原稿页边距与字号重建；
                        原稿页眉页脚、表格边框样式按设计不还原
dcr-source-kind:        pdf-textlayout
```

### 3.3 报告注记

**载体**：选了 2 审查意见报告时，注入报告的「总体评估」段末尾；**未选 2 时，改由终端汇总承担**（见 §3.5），不额外造文件。

内容只列**本次实际产出**的类型：

```
【保真说明】本次交付物的原稿贴合度：
           1 修订版       — 原稿级（以原稿为底，版式未动）
           3 清洁版       — 准原稿 B 级（拍照件无法还原版式，已按模板重建）
                           交付前请核对页眉页脚与公司抬头
           6 原文脱敏版   — 内容保真（脱敏已完成，版式不保证）
           本报告引用的原文均逐字取自原稿，未经模型改写。
```

> **`CONTENT_ONLY` 与 NEWDOC 项也要列**：不列等于默认"它没问题"，使用者无从判断。

### 3.4 退出码（**已裁决：开关控制，默认兼容**）

| 退出码 | 含义 | 触发条件 |
|---|---|---|
| `0` | 成功 | **默认行为**。即使有硬性项落在 QUASI_A/B 也返回 0 |
| `2` | 输入/用法错误 | 现状保留（spec 不存在、JSON 坏、类型全无效等） |
| **`3`** | **产出成功，但有硬性项未达原稿级** | **仅在传入 `--strict-fidelity-exit` 时**才可能返回 |

**开关语义**

```
python make-docx.py spec.json --source-docx 原稿.docx                          # 默认：退出码 0
python make-docx.py spec.json --source-docx 原稿.docx --strict-fidelity-exit   # 严格：未达标 → 3
```

**开关触发范围**：1 / 3 / 4 / 5 任一落在 `QUASI_A` / `QUASI_B`；7 在**有可用原稿却**落 `QUASI_*`。
**不触发**：2（引文保真，版式本就 NEWDOC）、6（内容保真，已放宽）、8/9/10（天然新建）。

> **为什么默认不返回 3**：现有全部调用方（`publish.py`、冒烟脚本、使用者自建流水线）都假定「0 = 成功」，
> 把 3 设成默认会让它们集体误判为失败，等于用一个校验改动打断整条发布链。
>
> **这不等于"静默"**：档位仍经**文件名、文档属性、报告注记、终端汇总**四处显式告知（§3.1–3.3、§3.5），
> 退出码只是给自动化用的信号，不是唯一告知渠道。

### 3.5 终端汇总（**无需选 2 也存在**）

每次运行结束在 stdout 打印，形如：

```
[保真汇总] 1 修订版     ORIGINAL     原稿做底，版式沿用
[保真汇总] 3 清洁版     QUASI_B      PDF 无版面信息，已按模板重建（页眉页脚未还原）
[保真汇总] 6 原文脱敏版 CONTENT_ONLY 内容已脱敏，版式不保证
[保真汇总] 未达标 1 项（受 --strict-fidelity-exit 控制，本次退出码 0）
```

这条汇总是**第四个外显渠道**，也是 §3.4 里"不算静默"的实际依据——**即使不选 2、不开开关，档位仍会打在屏幕上**。

#### 3.5.1 为什么「7 不算未达标」需要单独解释

同一轮运行里可能出现这样的反常观感：

```
[保真汇总] 3 清洁版     QUASI_B   ……（计入未达标）
[保真汇总] 7 原文照录版 QUASI_B   ……（不计入未达标）
```

7 也是 `QUASI_B`，却没被算进"未达标"，容易让人以为漏判。差异来自**档位要求类型不同**，不是程序偷懒：

| 交付物 | 要求类型 | 无原稿时落到 QUASI 是否算未达标 |
|---|---|---|
| 1 / 3 / 4 / 5 | `ORIGINAL_STRICT` | ✅ 算（任何情况下都必须原稿级） |
| 7 | `ORIGINAL_IF_AVAILABLE` | ❌ 不算（无原稿时降级即合规） |

即：**7 是"有原稿才必须原稿级"，1/3/4/5 是"任何情况都必须原稿级"。** 无原稿时，前者降级是设计允许，后者降级是未达标。

#### 3.5.2 汇总自动追加的解释行

终端汇总在检测到「**本轮存在未达标项，且 7 因无原稿走了 QUASI**」时，自动追加一行解释，把上面的差异直接打在屏幕上，无需人工联想：

```
[保真汇总] 说明：原文照录版（7）在无原稿时允许降级，故不计入未达标；
            其余修订版/红线/批注/清洁版必须原稿级。
```

> 该解释行**仅在触发条件成立时打印**，不影响"全达标"或"只选 2/6/7/8/9/10"时的简洁输出。

## 四、判定与分发的架构（治 D4）

### 4.1 单一档位解析器

新增一个函数，全流程唯一判定入口：

```python
def resolve_tier(slug, src_probe, produced_state) -> (tier, reason, source_kind):
    """返回该交付物本次实际落到的档位。纯函数，可单测。"""
```

`tier` 取值：`"ORIGINAL" | "QUASI_A" | "QUASI_B" | "CONTENT_ONLY" | "NEWDOC"`

**禁止**在生成函数内部各自决定档位——生成函数只负责「尽力做」，**做成了报成功、做不成报原因**，档位由解析器统一判。

### 4.2 数据流

```
prepare_source(原稿路径)
    ↓ 产出 src_probe = {kind, path, note, reason, layout_hints}
    ↓         kind ∈ word / ole2 / pdf_textlayout / pdf_textonly / ocr / paste / zip / other / missing
    ↓         layout_hints = {page_size, margins, font, size} | None
    ↓
produced_state = {}                       # 生成函数回填：{slug: "ok" | "fallback:<原因>"}
    ↓
for slug in types:
    doc = DOC_GEN[slug](spec)             # 生成函数：只返回 doc 或 None
    produced_state[slug] = "ok" if doc is not None else "fallback:<原因>"
    tier, reason, kind = resolve_tier(slug, src_probe, produced_state)
    meta = set_meta(doc, spec, slug, tier, reason, kind)
    name = outname(slug, tier)
    save(name)
    ↓
FIDELITY_LEDGER = {slug: (tier, reason)}
    ↓
① 写报告注记（选了 2 才有）  ② 打印终端汇总（恒有）  ③ 按开关决定退出码
```

> `produced_state` 由**生成函数回填、解析器只读**——这是"生成只管做事、档位统一判"的落地方式。
> 生成函数**不允许**自己声明档位（它不知道 src_probe 全貌，也不知道自己的产物该算什么档）。

### 4.3 要求类型清单（**代码真源**；§2.2 是它的自然语言说明）

> 同一套要求的两种呈现：**§2.2 给人读**，本节的 `TIER_REQUIREMENT` **给代码和门禁用**。
> 两者必须逐项一致，由 §4.3 末的门禁断言第 1–2 条守卫。**改动任何一处都要同时改另一处。**

```python
TIER_REQUIREMENT = {
    "tracked":  "ORIGINAL_STRICT",      # 1 修订版
    "report":   "CITE_FIDELITY",        # 2 审查意见报告（版式 NEWDOC，引文须逐字取自原稿）
    "clean":    "ORIGINAL_STRICT",      # 3 清洁版
    "redline":  "ORIGINAL_STRICT",      # 4 红线标记修订版
    "reportc":  "ORIGINAL_STRICT",      # 5 审查意见批注版
    "masked":   "CONTENT_ONLY",         # 6 原文脱敏版（已放宽：只管内容，不管版式）
    "original": "ORIGINAL_IF_AVAILABLE",# 7 原文照录版（有可用原稿必须 ORIGINAL，无则准原稿级）
    "diff":     "NEWDOC_ONLY",          # 8 文件比对报告
    "compare":  "NEWDOC_ONLY",          # 9 新旧比对
    "template": "NEWDOC_ONLY",          # 10 模板版
}
```

> 注意：字典按**新编号**排列，与 `TYPE_ORDER` 的顺序一致（`clean` 在 `redline` 之前）。
> 门禁会断言两者的键序也一致——不仅是键相同，**顺序漂移同样报错**。

**五种要求类型的语义（互斥，不得混用）**

| 要求类型 | 含义 | 允许落点 | 退出码 3 资格 |
|---|---|---|---|
| `ORIGINAL_STRICT` | **必须**原稿做底 | ORIGINAL ／ QUASI_A ／ QUASI_B | 落到 QUASI_* 即有资格 |
| `ORIGINAL_IF_AVAILABLE` | 有可用原稿则**必须**原稿级；无可用原稿可落准原稿级 | ORIGINAL ／ QUASI_A ／ QUASI_B | **仅**"有原稿却落 QUASI_*"才有资格 |
| `CITE_FIDELITY` | 版式 NEWDOC，引文须逐字取自原稿 | NEWDOC（版式） | 无 |
| `CONTENT_ONLY` | 只管内容正确，版式不限 | 任意档位 | 无 |
| `NEWDOC_ONLY` | 本就新建 | NEWDOC | 无 |

**`ORIGINAL_STRICT` 与 `ORIGINAL_IF_AVAILABLE` 的唯一区别**：后者在"本次根本没有可用原稿"时**不算未达标**（因为它本就不是硬要求），前者无论什么原因落到 QUASI 都算。

> 这个差异在终端观感上可能费解（7 同样是 `QUASI_B` 却没被计入未达标），**必须在 §3.5.2 的汇总解释行里显式说明**，不可只在设计文档里提一句。

门禁 `check.py` 从此断言四条：
1. **`TIER_REQUIREMENT` 的键集合必须与 `TYPE_ORDER` 相同**——少一个、多一个、拼错，当场报错。
2. **键的顺序必须与 `TYPE_ORDER` 一致**——顺序漂移同样报错（本次 3/4/5 重排正是这类风险）。
3. **值必须是上述五种要求类型之一**——防止新增错误拼法静默通过。
4. **落点与要求类型相容**——如 `NEWDOC_ONLY` 的产物不得标 `QUASI_A`。

这样「新增一类忘了登记要求」「要求类型拼错」「编号重排后字典没跟着调序」「要求与落点不相容」四种失效都变成不可能。

## 八、本设计**不做**的事（防止范围蔓延）
