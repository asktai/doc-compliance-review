```python
try:
    _sys.stdout.reconfigure(encoding="utf-8", errors="replace")
    _sys.stderr.reconfigure(encoding="utf-8", errors="replace")
except Exception:
    pass
```

`version.py` 原有旧块只设 stdout、且用 `errors="ignore"`——`ignore` 会静默吞字符，
`replace` 才看得出有字符没出去，故一并替换为统一版。stderr 也设：报错信息同样含中文。

**(1) 【低】CRLF/LF 不统一**（17 vs 39）—— 无混用，纯风格，未动。

### 二、D 盘路径：病灶不在 config.json

用户说"允许自定义但不做强制"。动手前先摸清现状，结果**病灶和预想的不一样**：

- `_config.tool()` 本身早就是"配置路径存在则用、否则回退 PATH"，运行时**从来不强制**；
- 真正的问题在 `_config.py` 的 **`DEFAULTS` 里硬编码着同一套 D 盘路径**。
  V3.8.6 只把随包 `config.json` 清空，却没动 DEFAULTS——config.json 留空时 `load()`

改法是把"本机"这一层彻底挪出去，三层各司其职：

| 层 | 内容 | 随包 |
|---|---|---|
| `DEFAULTS` | tools 全空 | — |
| `config.json` | tools 全空 | ✔ |
| `config.local.json` | 本机自定义 | ✘ 不进 git、不随包 |

- `_config.load()` 三层叠加，任一層坏了跳过它用上一层（不阻断主流程）
- `detect-tools.py --write` 改写本机覆盖层；新增 `--write-config` 留给"整包拷走"
- `check.py` 由"路径不存在即告警"改**三级**：有效→info；失效但 PATH 可兜→info；PATH 也没有→才 warn
- `check_hardcoded_paths()` **取消对 `_config.py` 的豁免**——DEFAULTS 既已清空，
  任何 .py 都不该再出现盘符字面量，从此谁再塞本机路径进代码会被当场抓住
  （`check.py` 自身仍豁免，检测正则自指无法自检）

### 三、验证

## 2026-09-25 V3.11.0 交付物新增 HTML 格式（网页浏览版·单文件·零外链）

### 一、起因与确认

用户："增加一个导出文件html版"。这是**新增格式**，有两条路线可走，不能自己拍：

1. **形态**：打印版（纯静态、像 PDF 的网页）／**网页浏览版（带交互）**／两者都要；
2. **依赖**：强制装 `markdown` 库／**优先用库、缺失才降级**／完全自研不依赖。

用 AskUserQuestion 问，用户选：**网页浏览版（带交互）** ＋ **优先 markdown 库、缺失才降级**。
这两个选择决定了后面的全部实现——交互要真有用（不是摆设），依赖必须能兜底（不能让没装库的
用户出不了件）。

### 二、实现：不另起炉灶，复用既有 MD 通道

关键判断：**`MD_GEN` 本就已覆盖全部 10 类交付物**。所以 HTML 不需要在文档生成层新写 10 套逻辑，
直接 `md_to_html(MD_GEN[t](spec))` 即可——**零新增文档结构、10 类天然全覆盖**，
且 MD 与 HTML 永远同源（改一处两边同步，不会出现"MD 是一套、HTML 是另一套"的分裂）。

`make-docx.py` 新增段（插在 `MD_GEN` 之后、`main()` 之前）：

| 函数 | 职责 |
|---|---|
| `_risk_spans(s)` | ★/★★/★★★ → `<span class="risk r1/r2/r3">`（三色标签） |
| `_esc_keep(s)` | 转义 `<` `&` 但放行白名单内联标签（`ins/del/br/span/strong/em/code/b/i`）——修订版要保留 `<del>/<ins>` 语义，不能一刀切转义 |
| `_split_row(line)` | 管道表格拆格 |
| `_md_fallback(md)` | 自研降级转换器：ATX 标题/引用/分隔线/管道表/列表/段落 ＋ 行内 |
| `md_to_html(md_text)` | 优先 `_mdlib.markdown`，**异常或缺失均降级**，不抛错 |
| `html_page(slug, spec, body)` | 包成单文件网页 |

`main()` 分发只加 3 行：

```python
if "html" in fmts and t in MD_GEN:
    name = outname(t, "html")
    open(...).write(html_page(t, spec, md_to_html(MD_GEN[t](spec)))); made.append(name)
```

### 三、单文件网页的三条硬约束

1. **零外部资源**：CSS/JS 全内联。验收时用 `src="http` / `href="http` 全量扫描，10 个文件全过。
   意义是**断网可开、转发给别人直接双击就能看**，不需要连服务器、不会有字体/脚本加载失败。
2. **目录锚点服务端生成**：`re.sub(r"<h([23])[^>]*>(.*?)</h\1>", _mk, body, flags=re.S)` 回填
   `id="s%d"`。不用 JS 算锚点——**禁 JS 的环境也能跳转**，这是"能交付"和"碰运气"的区别。
3. **打印即排版**：`@media print{@page{size:A4;margin:16mm}}` 并隐藏导航与按钮，
   浏览器 Ctrl+P 直接得到 A4 版心干净的 PDF——等于**白送一个 PDF 通道**（且不依赖 LibreOffice）。

交互三件套：顶部固定目录导航（`.topbar`＋`nav.toc`）、h2/h3 点击折叠（`::after ▾/▸`）、
全部折叠/展开＋打印按钮。三色标签色值与 SKILL.md 三色分级**同一套**（高 `#d8443c` 红／
中 `#e3a637` 橙／低 `#3e9b6b` 绿），不另造色板。

### 四、踩坑：验证脚本的 spec 字段对不上代码约定

首轮离线验证只出 **8 个** HTML，缺 `original`（照录版）与 `masked`（脱敏版）。追下去是两层原因：

前者按规范是给人看的英文可读名（`display_name_en`），后者必须是 slug（`name`）——
平台侧识别技能靠 slug，英文名里带空格和中点，塞进头部元数据会被 downstream 当成普通字符串。
顺手写成同一个值的话，出包不报错、解包也不报错，要等到别的工具读头部才发现不对。
所以在 `package_stem` 的 docstring 里留了明确说明＋"不要从文件名反解"。

### 三、两个不敢只改一半的地方

1. **扩展名**：原先两处硬写 `"%s.skill" % stem`，只改 `FMT_EXT` 常量的话，zip／skill 两种产物的
   扩展名就会一边大写一边小写。统一改成 `"%s.%s" % (stem, FMT_EXT[...])`，把硬编码字符串消干净。
2. **文件名不可反解**：产品名和英文名都可能含空格、中点，甚至下划线（`_`，与分隔符同形），
   按 `_` 切必错位。头部元数据一律从 `package_stem` 的返回值取，不 `split` 文件名。

### 四、守卫与负向测试

新增 `STEM_RE` ＋ `verify_filename()`，`build()` 出包前自测，不合规范直接中止（不允许手工改名绕过）。
报错要指到具体段（日期段／技能 ID 段），不能笼统一句"格式不对"。
负向测试 5 例：旧短横线四段式、缺半角括号、日期未紧凑、日期段位数不对、技能 ID 段非括号包裹——全被拦下。

这已经是第四次在同一类事上栽跟头（口径漂移）：V3.10.1 卡片数字、V3.10.2 触发词、
V3.11.1 格式数／菜单项数／内置库数、这次的包命名。

规范能不能被执行，**不取决于写得多醒目，取决于有没有一条会被真的跑到的断言**。
